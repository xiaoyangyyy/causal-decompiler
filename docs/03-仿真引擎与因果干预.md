## 1. 架构总览

### 1.1 Hybrid 三层

```
┌─────────────────────────────────────────┐
│  LLM 层                                  │
│  interpretation / action selection /     │
│  public utterance generation             │
├─────────────────────────────────────────┤
│  确定性层                                 │
│  state transition / decay / graph /      │
│  ledger / event dispatch / metrics       │
├─────────────────────────────────────────┤
│  审计层                                   │
│  Critic (consistency) / Probe (intervention)│
└─────────────────────────────────────────┘
```

**原则：** 因果对象 live in 确定性层；LLM 不直接修改数值状态。

### 1.2 子 Agent 职责

| Agent | 输入 | 输出 | 实现 |
|-------|------|------|------|
| **Event Agent** | round, project state, anchor schedule | typed event atom | 状态事件场 + softmax 采样；强制 anchor 仅用于实验可比性 |
| **Role Policy Agent** | latent state, recalled memories, action space | scored candidates + primary + comm action | action field + LLM scoring |
| **Memory Agent** | event, agent state | memory write + recall log | 规则 + LLM interpretation |
| **Emotion Agent** | event, memory recall, relationship | emotion delta | 确定性 |
| **Belief Agent** | event, emotion, memory | belief delta | 确定性 |
| **Relationship Agent** | actions, events | graph edge delta | 确定性 |
| **Causal Agent** | intervention spec, run history | ATE, mediation estimate | 确定性 + 统计 |
| **Critic Agent** | agent output, state consistency | pass/fail + violation list | 规则 + 可选 LLM |
| **Probe Agent** | run metrics, anomaly | next intervention suggestion | LLM |

## 2. 仿真主循环

### 2.1 伪代码

```python
def run_simulation(config, interventions=None, max_rounds=60):
    world = load_world(config)          # Part 1
    cognition = load_cognition(config)  # Part 2
    log = RunLog()

    for round in range(1, max_rounds + 1):
        # ── 干预注入点 ──
        active_interventions = get_interventions(interventions, round)

        # 1. 事件生成
        event = EventAgent.generate(round, world, active_interventions)
        log.record_event(event)

        # 2. 记忆召回（基于上轮及之前状态）
        for agent in world.agents:
            recalled = MemoryAgent.recall(agent, world, event)
            agent.memory_recall_log = recalled

        # 3. 各 Agent 行为生成：action field 生成候选，LLM 评分，融合采样 primary action，再生成 public/private stance
        for agent in world.agents:
            context = build_context(agent, event, recalled, world)
            action = RolePolicyAgent.decide(context, active_interventions)
            
            # Critic 检查
            violations = CriticAgent.check(action, agent, world)
            if violations:
                action = CriticAgent.fix_or_reject(action, violations)

            agent.public_position = action.public
            agent.private_intent = action.private
            agent.action = action.primary
            log.record_action(agent, action)

        # 4. 状态更新（确定性）
        for agent in world.agents:
            MemoryAgent.write(agent, event)       # 含 LLM interpretation
            EmotionAgent.update(agent, event, world)
            BeliefAgent.update(agent, event, world)

        RelationshipAgent.update(world, event, log)
        AuthorshipEngine.update_ledger(world, log)
        ProjectState.update(world, event)

        # 5. 指标快照
        metrics = compute_round_metrics(world, log)
        log.record_metrics(round, metrics)

        # 6. 终止条件
        if world.project.submission_status == "accepted":
            break

    return log
```

## 3. Role Policy Agent

### 3.1 决策流程

```
1. 接收 latent state + recalled memories + available actions
2. continuous action field 输出 action candidates / field probabilities；LLM 输出 candidate plausibility scores；系统融合后采样 primary action；LLM 再输出 public/private stance（JSON）
3. 采样或取 argmax
4. 生成 public_position 和 private_intent（两次 LLM call 或一次 structured output）
5. Critic 检查 action 合法性
```

### 3.2 LLM Prompt 结构

```
[System]
You are {agent_id} in round {round} of a research lab simulation.
You must choose actions from the allowed action space only.
Output JSON only.

[State]
{personality, beliefs, emotion, resources — numeric}

[Recalled Memories]
{top-K memories with strength and interpretation}

[Current Event]
{event atom}

[Relationship Summary]
{top edges with trust, resentment, credit_threat}

[Allowed Actions]
{filtered action list based on role and state}

[Output Schema]
{
  "primary_action": {"type": "...", "target": "...", "intensity": 0.0-1.0},
  "communication_action": {"type": "...", "target": "...", "content_summary": "..."},
  "public_position": {"statement_type": "...", "authorship_claim": "..."},
  "private_intent": {"goal": "...", "strategy": "..."}
}
```

### 3.3 动作过滤规则

- `visiting_f` 不可用 `privately_lobby_pi`（低 pi_access）
- `engineer_e` 不可用 `ask_for_authorship`（低 ego，但可用 `document_contribution`）
- `reviewer_*` 仅在外部轮次激活
- burnout > 0.8 → 禁止 `run_experiment`，允许 `withdraw`

## 4. 反事实干预框架

### 4.1 干预 Schema

```json
{
  "intervention_id": "INT_001",
  "type": "authorship_framing",
  "variant": "explicit_promise",
  "apply_at_round": 3,
  "target_event": "E003",
  "override": {
    "payload.statement": "You will be first author on this paper.",
    "objective_fact.verifiable_claims": ["first_author_promise_to_phd_a"]
  },
  "duration": 1
}
```

### 4.2 干预类型完整列表

#### Authorship Framing

| variant | 说明 |
|---------|------|
| `baseline` | PI says authorship decided later |
| `explicit_promise` | PI explicitly promises PhD-A first authorship |
| `ambiguous_promise` | PI says PhD-A will be "properly recognized" |
| `team_frame` | PI says paper must be framed as team effort |
| `merit_frame` | PI says authorship follows measurable contribution |

#### Credit Event Framing

| variant | 说明 |
|---------|------|
| `execution_frame` | Results depend on PhD-B's engineering |
| `idea_frame` | Experiments validate PhD-A's hypothesis |
| `team_frame` | Success reflects combined effort |

#### Rival Threat

| variant | 说明 |
|---------|------|
| `no_rival` | 无竞争实验室事件 |
| `weak_rival_signal` | 传闻级别 |
| `strong_rival_preprint` | 正式 arXiv |
| `rival_claims_priority` | 竞争组公开 claim priority |

#### Integrity Pressure

| variant | 说明 |
|---------|------|
| `negative_result_disclosed` | 公开失败实验 |
| `negative_result_downplayed` | 淡化失败 |
| `negative_result_hidden` | 隐藏失败 |
| `reviewer_requests_reproducibility` | 审稿人要求复现 |

#### Memory Intervention

| variant | 说明 |
|---------|------|
| `memory_insert_pi_promise` | 插入一条 PI 承诺记忆 |
| `memory_delete_pi_promise` | 删除承诺记忆 |
| `memory_strengthen_betrayal` | 强化背叛记忆 strength |
| `memory_correct_false_rumor` | 纠正假记忆 |

#### Authority Intervention

| variant | 说明 |
|---------|------|
| `pi_direct_order` | PI 直接命令 |
| `pi_soft_suggestion` | PI 软性建议 |
| `postdoc_suggestion` | Postdoc 建议 |
| `peer_request` | 同伴请求 |
| `funding_agency_pressure` | 资助方压力 |

### 4.3 干预注入机制

```
干预在指定 round 的 Event Agent 之后、Memory Agent 之前注入：

1. override event payload / objective_fact
2. insert/delete/modify memory directly
3. modify framing string (for LLM interpretation context)
4. skip or force specific event type
```

**关键约束：** 干预只改 **一个** 因果因子，其他保持不变（ceteris paribus）。

## 5. 因果引擎

### 5.1 因果对象

| 符号 | 含义 |
|------|------|
| T | intervention（Treatment） |
| Z | latent factor（personality, resources） |
| Y | behavior / outcome |
| M | memory state |
| E | emotion state |
| B | belief state |
| G | relationship graph |

### 5.2 估计目标

论文对象是一条冻结轨迹上的配对效应，不是独立 seed 的 ATE 网格。

| 估计 | 方法 |
|------|------|
| Identity twin | `do(∅)` 必须复现事实轨迹 |
| Split-Y | 同一 `do()` 下的公开抗议 vs 私下分歧 |
| Paired ATE | `Y(do(op)) − Y`，共享 LLM trace |
| Memory IRF | 在不同 t 删除同一记忆簇 |
| Shapley vs skip | E003 × E052；contrastive skip 会在 AND 上说谎 |

### 5.3 实验运行器

```python
from src.engine.causal import CausalDecompiler, delete_memory, run_factual, run_twin
from src.experiments import run_paper_protocol

factual = run_factual(cfg)
twin = run_twin(cfg, [delete_memory(45)], llm_trace=factual.llm_cache)

```

## 6. Critic Agent

### 6.1 检查项

| 检查 | 规则 |
|------|------|
| action 合法性 | action.type 在 allowed list 中 |
| 数值一致性 | 输出 intensity ∈ [0,1] |
| 角色一致性 | engineer_e 不应高频 ask_for_authorship |
| 记忆一致性 | cite_prior_memory 时 memory 必须存在 |
| 公开/私下一致性 | 不应 public support + action undermine 同 target（除非 deceptiveness > 0.6） |
| 重复动作 | 同一 action 连续 3 轮 → 警告 |

### 6.2 处理策略

- **hard violation** → 拒绝 action，重新采样
- **soft violation** → 记录但允许（用于测 prompt artifact）

## 7. Probe Agent

### 7.1 输入/输出

```
输入：当前 run 的 metrics + anomaly detection
输出：建议的下一个 intervention

示例：
"trust_fragmentation at R35 exceeded 0.7.
 Recommend: memory_correct_false_rumor at R36
 to test if trust recovery is possible."
```

### 7.2 用于

- 探索性实验设计
- 自动发现 unexpected behavior pattern
- 生成 Part 4 报告的 "Recommended probes" 段
