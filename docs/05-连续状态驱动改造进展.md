# LabWars 连续状态驱动改造进展

> 这是历史改造记录，不是论文协议。当前实验入口见 [`18-Causal-Decompiler-Paper-Protocol.md`](18-Causal-Decompiler-Paper-Protocol.md)。
>
> 更新时间：2026-06-28  
> 目标：把 LabWars 从“规则触发剧情 / 阈值触发行为”推进为“连续状态驱动的社会动力学仿真”。

---

## 1. 当前结论

这轮改造已经完成了最关键的一步：

**Agent 的行为不再由单一事件、硬阈值或 LLM 直接拍板触发，而是由连续心理场生成多个候选动作，再通过 softmax / sampling 选出最终动作。**

现在每轮行为生成会综合：

- 当前情绪：anger、resentment、anxiety、burnout、loyalty 等
- 记忆场：recall valence、recall strength、记忆类型
- 关系图：trust、resentment、dependency、credit threat
- 资源与职业压力：PI 依赖、外部网络、deadline、funding pressure
- 人格倾向：credit sensitivity、authority dependence、conflict avoidance、cooperation
- 项目压力：authorship conflict、rival threat、integrity risk、team morale
- 近期行动惯性：重复行为只降低倾向，不再硬禁止

这意味着类似：

```python
if resentment > 0.7:
    confront()
```

这种机制已经从核心行为路径中移除。

```text
  ↓

```

## 3. 已删除 / 连续化的阈值残留

### 3.1 行为禁用阈值

原来：

```python
if burnout > 0.8:
    blocked.add(ActionType.RUN_EXPERIMENT)
```

现在：

- burnout 不再硬禁任何合法动作
- fatigue 进入 action tendency
- 高 burnout 只会平滑降低研究动作倾向

影响文件：

- `src/world/actions.py`
- `src/engine/action_selection.py`

---

### 3.2 Prompt 里的公平阈值

原来 prompt 中有：

```text
if beliefs.pi_fairness >= 0.55 ...
if pi_fairness < 0.35 ...
```

这会让 LLM 模拟“规则档位”，不是连续状态。

现在：

- prompt 不再按 pi_fairness 档位指导行为
- LLM 必须尊重 sampled action
- LLM 参与 candidate plausibility scoring，并在 selected action 约束下生成公开话术、私下意图和动机解释

影响文件：

- `src/engine/prompts.py`
- `src/engine/role_policy.py`

---

### 3.3 行为重复硬禁止

原来：

```python
if repeated_action_count >= N:
    avoid(action)
```

现在：

- 重复行为不再被硬禁止
- 近期重复次数进入 tendency penalty
- 行为惯性仍存在，但不会被规则强行截断

影响文件：

- `src/engine/diversity.py`
- `src/engine/action_selection.py`
- `tests/test_engine/test_diversity.py`

---

### 3.4 情绪 / 信念更新阈值

原来存在类似：

```python
if intensity > 0.5:
    add_shock()
```

现在：

- escalation feedback 使用连续 `impulse_response`
- 正负 shock 使用 `logistic_gate`
- cluster / resentment / unfairness 组合使用连续门控

影响文件：

- `src/cognition/belief.py`
- `src/cognition/dynamics.py`
- `src/cognition/emotion.py`
- `src/cognition/pipeline.py`

---

### 3.5 记忆召回阈值

原来 recall audit 中仍有：

```python
if weight > ...
```

现在：

- 所有 memory 都通过 attention weight 参与
- `recalled_memories` 不再是阈值筛选结果
- recall field 是连续加权场

影响文件：

- `src/cognition/memory.py`

---

### 3.6 Probe 阈值

原来：

```python
if trust_fragmentation > 0.55:
    suggest_probe()
```

现在：

```json
{
  "variant": "memory_correct_false_rumor",
  "activation": 0.7342,
  "reason": "trust_fragmentation=..."
}
```

Probe 不再“触发 / 不触发”，而是每个 probe 都有连续 activation score。

影响文件：

- `src/engine/probe.py`

---

### 3.7 Outcome 二值阈值

原来 `protest_authorship` 是硬二分类：

```python
if score >= 0.22:
    return 1.0
return 0.0
```

现在：

```python
protest_authorship = continuous propensity in [0, 1]
```

它由：

- escalation potential
- action pressure
- compliance pressure

平滑组合得到。

影响文件：

- `src/engine/run_log.py`
- `tests/test_engine/test_outcomes.py`

---

### 3.8 Divergence 高峰筛选

原来：

```python
if divergence >= threshold:
    peaks.append(round)
```

现在：

- 每轮 divergence 都计算 activation
- 报告中展示连续排名，不做硬筛选

影响文件：

- `src/experiments/metrics.py`
- `src/experiments/report.py`

## 4. 当前仍保留的判断

有些 `if` 仍然保留，但它们不是社会动力学阈值。

### 4.1 合法性检查

例如：

```python
if action_type not in allowed_actions:
    hard_violation
```

这是 schema / action space 合法性，不是行为触发规则。

### 4.2 空值与除零保护

例如：

```python
if denom < 1e-12:
    return 0.0
```

这是数值安全保护，不是仿真逻辑。

### 4.3 typed event 分派

例如：

```python
if event.type == "rival_preprint":
    add rival anxiety weight
```

这是事件类型语义，不是状态阈值。事件仍然是 typed atom，这是项目设计原则之一。

当前扫描结果中剩余的数值比较主要是：

- `src/experiments/metrics.py` 中的除零保护
- `src/engine/action_selection.py` 中的 typed event 加权

## 5. 当前行为生成的实际效果

以 PhD-A 为例，现在他是否质疑 PI，不再由一个值决定，而是由多个方向拉扯：

### 推向质疑

- authorship anxiety
- credit capture
- resentment drive
- negative memory field
- perceived credit threat
- promise broken memory

### 阻止质疑

- career pressure
- authority pressure
- PI dependency
- conflict avoidance
- low external network
- recommendation / graduation pressure

### 最终行为

不是：

```text
怨恨超过 0.7 → confront
```

而是：

```text
confront tendency = f(resentment, authorship anxiety, authority pressure, caution, memory field...)
document_contribution tendency = f(credit capture, caution, integrity pressure...)
privately_lobby_pi tendency = f(authorship anxiety, career pressure, caution...)
comply tendency = f(authority pressure, career pressure, caution...)

softmax → sampling
```

因此同一状态下不同 seed 会出现合理波动，但不是纯随机。

## 10. 还没做但建议下一步做

当前最大剩余问题不是行为阈值，而是：

**事件系统仍然偏固定 60 轮剧情表。**

下一步建议补：

### 10.1 State-driven Event Agent

现在：

```text
round 30 → E030
round 40 → E040
round 52 → E052
```

建议改成：

```text
event probability = f(project pressure, trust fragmentation, authorship conflict, rival threat, memory tension)
```

也就是说：

- E040 贡献争论不是固定发生
- 它应该由 authorship_conflict、credit_threat_density、public_private_divergence 平滑提高概率

### 10.2 Anchor 只保留最小骨架

建议把事件分成：

- hard anchor：必须发生的世界节点
- soft anchor：有较高先验概率，但可被状态推迟、弱化、跳过
- emergent event：完全由状态生成

### 10.3 Report 进一步利用 motive log

报告可以新增：

```text
Action Motive Decomposition
```

例如：

```text
PhD-A R47 withdraw threat:
- authorship_anxiety: 0.71
- resentment_drive: 0.64
- career_pressure: 0.48
- caution: 0.39
- credit_capture: 0.69
```

这样报告会更像“反编译”，而不是故事复述。

### 新的事件生成机制

现在每一轮非强制 anchor 不再只是读取 YAML 剧情，而是先生成事件候选：

```text
event_probability = softmax(
  f(
    authorship_dispute_index,
    credit_threat_density,
    trust_fragmentation,
    first_author_gap,
    recent_private_lobbying,
    recent_documentation,
    withdrawal_pressure,
    authorship_memory_pressure,
    betrayal_memory_pressure,
    deadline_pressure,
    rival_threat,
    integrity_risk
  )
)
```

候选事件包括：

| 候选事件 | 来自哪些连续压力 |
|---|---|
| `authorship_ambiguity` | 署名争议、deadline、PI 依赖、PhD-A 署名记忆压力 |
| `private_lobbying` | 最近私下游说、credit threat、PhD-B 相对署名优势 |
| `narrative_change` | contribution documentation、credit threat、writing progress |
| `external_history` | betrayal memory、trust fragmentation、withdrawal pressure |
| `rival_preprint` | rival threat、novelty risk、deadline pressure |
| `integrity_dispute` | integrity risk、selective reporting、trust fragmentation |
| `deadline_shift` | deadline pressure、实验/写作不足 |

这意味着：同一个 seed/同一个状态会稳定复现；不同状态会自然改变事件倾向。

### 新的记忆机制

之前：

```text
新事件 -> 写入一条新 memory
旧 memory 基本只 decay / recall
```

现在：

```text
新事件 -> 先召回旧 memory -> 按 attention/plasticity 改写旧 memory -> 再写入新 memory
```

每条被再巩固的旧记忆会记录：

```json
{
  "round": 30,
  "event_ref": "E030",
  "attention": 0.42,
  "plasticity": 0.13,
  "valence_before": 0.65,
  "valence_after": 0.48,
  "strength_after": 0.61
}
```

这一步很关键，因为真实冲突不是“记住事实”，而是“旧事实被新解释重新染色”。

### PI 权力面现在如何工作

PI 不再只是一个普通 agent，而是制度性控制节点：

```text
pi_control_surface = {
  recommendation_letter,
  funding_access,
  authorship_veto,
  resource_allocation
}
```

这些控制面由以下变量连续生成：

| 控制面 | 主要来源 |
|---|---|
| recommendation_letter | PI ambition、funding pressure、authorship conflict |
| funding_access | PI ambition、funding pressure、deadline pressure |
| authorship_veto | PI ambition、authorship conflict、deadline pressure |
| resource_allocation | deadline pressure、team morale、PI cooperation |

Agent 对 PI 的依赖不再只是“怕不怕 PI”，而是：

```text
career_hostage_index = f(
  PI institutional control,
  agent authority dependence,
  PI access,
  lack of external network
)
```

这更接近真实学术关系：学生不是因为一个情绪阈值不敢反抗，而是因为推荐信、资金、资源、投稿裁决同时压着他。

### ledger 现在更像真实贡献账本

之前主要是：

```text
document_contribution -> ledger += small delta
```

现在变成：

| action | ledger 影响 |
|---|---|
| `run_experiment` | experiments + data |
| `improve_baseline` | experiments + code |
| `debug_code` | code + experiments |
| `write_section` | writing + idea |
| `analyze_failure` | experiments + data + code |
| `prepare_rebuttal` | rebuttal + writing |
| `share_result` | data + experiments |
| `document_contribution` | idea + experiments + code + data + writing |
| `notify_program_officer` | funding |

并且每个增量还会乘以 agent 的资源/人格适配度：code control、data control、writing control、ambition、cooperation、PI access 等都会影响 ledger 增量。

### LLM 现在不能偷偷改动作含义

动作仍由连续 action field 采样决定。LLM 只写公开话术和私下意图。

新增 critic audit：

| audit code | 含义 |
|---|---|
| `llm_public_action_drift` | 公开话术和 sampled action 弱不一致 |
| `llm_private_strategy_drift` | 私下策略解释不了真实动作 |
| `sampled_action_overridden` | LLM 或 normalize 试图覆盖 sampled action，硬违规 |

这保证系统不会退回“LLM 自己写剧情”。

## 2026-06-29 审计修正：LLM Candidate Scoring 已进入行为选择

上一版（已被本轮替换）真实流程是：

```text
continuous action field 采样 primary action
LLM generates public_position / private_intent / interpretation under the sampled-action constraint
```

这一版已经升级为：

```text
continuous action field generates candidates
LLM scores candidate plausibility
field_score + llm_score 融合
softmax / seeded sampling 选择 primary action
LLM renders public/private stance under selected-action constraint
```

也就是说，LLM 现在不再只是“解释已经选好的动作”，而是通过 candidate scoring 真实影响行为概率；但它仍不是自由行动策略，不能在 rendering 阶段越权改写 selected action。

关键代码路径：

| 环节 | 文件 |
|---|---|
| structural candidates | `src/engine/action_selection.py` |
| LLM candidate scoring | `src/engine/role_policy.py` |
| scoring prompt | `src/engine/prompts.py` |
| selected action 锁定与 drift 审计 | `src/engine/role_policy.py` + `src/engine/critic.py` |

融合形式：

```text
fused_tendency = field_tendency + llm_action_score_mix * (llm_score - 0.5)
probability = softmax(fused_tendency)
selected_action = sample(probability)
```

更准确的项目表述是：

> LabWars uses continuous latent action fields as a structural behavioral prior, asks LLMs to score candidate action plausibility under subjective memory and relationship context, then samples actions from the fused field.

这解决了之前“LLM 没有真正参与 action selection”的硬伤，同时保留可复现、可消融、可审计的仿真骨架。

## Action Field 支持运行时消融

新增：

```text
src/experiments/action_field_ablation.py
```

可以这样比较 baseline 和某组权重改动：

```python
from src.engine.simulation import SimConfig
from src.experiments.action_field_ablation import run_action_field_ablation

    SimConfig(max_rounds=60, interventions=[]),
    {

            "confront": {"resentment_drive": 0.0}
        }
    },
    seeds=list(range(10)),
    outcome="authorship_escalation_score",

```

这用于回答：

```text

```

因此现在可以明确区分：

| 层 | 当前状态 |
|---|---|
| 仿真动力学 | 尽量连续化、无硬阈值触发 |
| 行为生成参数 | YAML 配置化，可校准、可消融 |
| LLM 角色 | candidate scoring + public/private/interpretation 生成，不自由覆盖 selected action |
| 报告指标 | 可以有解释性切分，但必须声明只是观测摘要，不是动力学机制 |
